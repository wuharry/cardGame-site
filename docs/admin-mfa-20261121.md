# 首次驗證 App 設定修復（2026-11-21）

正式後台顯示「驗證 App 設定回覆不完整」。本機用 Supabase 的 SVG 產生器格式重現同樣錯誤：原本只接受以 `<svg` 開頭的文字，但 SVGo 會在 SVG 前加 XML 宣告和註解。

修正只將宣告、前置空白與註解排除於根元素檢查，保留原圖內容，仍透過編碼後的圖片 URL 顯示。非 SVG、錯誤 MIME 格式、超過上限及缺少有效 factor／secret 的回覆仍拒絕並登出。會員權限、信箱驗證、TOTP 驗證和新密碼規則不變。

驗證：修復前新增的真實回覆格式測試失敗；修復後登入 API **57 項通過**，TypeScript、ESLint 通過。隔離環境的正式建置、桌面／手機統計頁與管理介面、390／1440 寬度官網瀏覽器回歸均通過；畫面證據在 `shots/mfa-20261121`。瀏覽器測試使用替代後端回覆，沒有向正式資料庫寫入測試資料。

密碼重設由管理員本人完成信箱驗證、驗證 App 和新密碼輸入；本次沒有設定或接收使用者密碼。

來源：[Supabase MFA 產生流程](https://github.com/supabase/auth/blob/master/internal/api/mfa.go)、[SVGo 的 XML 前綴](https://github.com/ajstarks/svgo/blob/master/svg.go)。這些來源支持格式相容性的原因；實際登入成功仍須在部署後由管理員驗證。
